Keep only what teaches.

We construct a new event from known scenario definitions. We never accept arbitrary error messages, event uploads or customer data through the API.

Kept
Generated event ID, timestamp, fixed scenario message, release, service and normalized stack frame.
Discarded
User identity, email, IP, cookies, HTTP headers/bodies, query strings, hostnames, absolute paths, breadcrumbs and extra context.
Not enabled
Replay, profiling, automatic instrumentation, tracing, logs and client reports.
Retention
Last 200 local events and up to 20 examples per issue. Restart or clear the session to discard the dataset.

Sandbox / architecture

Real SDK. Deliberately small app.

Your integration work is the project. Sentry's platform belongs to Sentry.

01

Controlled failure

A fixed TypeScript function throws. The server catches it and creates a dedicated capture scope.

02

SDK capture

The official Node SDK generates an event and parses the exception stack. Automatic integrations are disabled.

03

Local transport

An allowlist rebuilds the event. A custom transport retains a safe projection; it never sends a request to Sentry.

04

Issue workflow

This original demo groups by scenario. Resolve, reopen and recapture to explore a simple regression workflow.

What this is

An independent portfolio integration using @sentry/node, plus an original UI, safe-payload boundary, test suite and in-memory issue workflow.

What it doesn't reproduce

Sentry's ingestion service, grouping algorithms, distributed tracing, multi-user permissions, storage platform, alerts and production scale. The local inbox is a teaching tool.
